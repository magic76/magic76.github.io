# Crew Web i18n foundation

## Scope and source of truth

The UI locale is separate from the Crew Teacher learning language and from the Gemini Live / Friend conversational language. Changing UI language must never rewrite learning targets, tutor voice, session prompts, memory, or a live chat's language.

Phase one localizes the global chrome, home dashboard, settings (including memory, backups, Gemini Key and microphone diagnostics), and the Crew Briefing **preview** on the home dashboard.

Phase two localizes Teacher practice, Learn, My learning, the role switcher, teacher selection and tutor session setup; Friends directory, profile, and memory actions; Story shelf, creation, and personal preferences; Fortune home, history, and primary reading form / AI result states. All locale dictionaries are separated by product.

**Still pending:** vocabulary/course lesson content, teacher and friend live-session controls, full Story editor/player/physical-book flows, Fortune result interpretation tabs, and full Briefing archive/articles. Do not present untranslated AI-generated content as English. Avoid translating raw model prompts with interface i18n: spoken language and AI content are independently configured.

## Supported interface languages

- `zh-TW`: Traditional Chinese, default fallback.
- `en`: English.
- Public URLs determine the UI locale: unprefixed routes are always Traditional Chinese. Explicit locale prefixes and manual language switching remain supported. No automatic browser-language or saved-preference redirects. Only legacy HashRouter uses the stored `crew_ui_locale_v1` preference.
- Updating the UI also updates `<html lang>` and the browser tab's title. This does **not** provide search-engine-visible HTML on its own.

## Adding interface copy

Use `useTranslation("common"|"home"|"settings"|"teacher"|"friends"|"story"|"fortune")` from `react-i18next` and `t("namespaceKey")` instead of adding literal UI strings.

Translation resources: `web-spa/src/i18n/locales/{zh-TW,en}/{common,home,settings,teacher,friends,story,fortune}.json`. Keep both locales' key sets identical and test with `npm test`. For later Teacher, Friends, Story, Fortune and Briefing pages add a product-specific namespace, not another global locale preference.

The UI language selector is in the persistent header and Settings. Content that's explicitly generated by Gemini, past user conversation, user-supplied book text, friend names, and generated research content must not be mechanically translated by UI i18n.

`react-i18next` currently declares optional TypeScript peers only through TS 6, while this project uses TypeScript 7. The repository's temporary `.npmrc` peer setting permits installation; keep the dependency lockfile pinned and remove the workaround after upstream peer metadata expands.

## Later public SEO pages

Existing Web App routes stay under `/crew-app/#/...`. Public indexable landing pages will use:
- `/`, `/teacher`, `/story`, `/fortune`, `/research` for Traditional Chinese.
- `/en/`, `/en/teacher`, `/en/story`, `/en/fortune` when equivalent English pages are published.

Static SEO pages need separate `hreflang`, canonical, sitemap and language-specific HTML. React title changes do not replace static rendering; do not index pages that have only untranslated dynamic content.
