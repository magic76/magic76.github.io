# Crew Gemini Live keyboard conversation

## Design

Teacher and Friend share the existing `crew-live.js` WebSocket transport.
For a **BYOK user** in text mode, the UI now creates a persistent Live session with `textOnly:true`.
It sends keyboard input with `clientContent.turns` and `turnComplete:true`, exactly as the existing Live transport's `sendText()` does.

The `gemini-3.8-live` native audio agent uses `responseModalities:["AUDIO"]` plus `outputAudioTranscription:{}`. The app displays the output transcript (or an inline text fragment if received), not the audio. Google documents AUDIO as the supported response modality for native audio Live models, even though the model card lists Text and Audio outputs:
- https://ai.google.dev/gemini-api/docs/live-api/capabilities
- https://ai.google.dev/gemini-api/docs/models/gemini-3.8-live

`textOnly` means **no microphone permission, no AudioContext, no audio capture/worklet, no audio playback, no wake lock, no automatic first greeting**. Audio can still be generated by Google and billed upstream; suppressing browser playback does not eliminate Google audio token charges. Do not claim text-only Live has the same cost as Gemini generateContent.

## Scope and boundaries

- BYOK text: same Live model/role/language used by voice, but a fresh keyboard session when navigating modes. Text turns reuse one connected WebSocket until the user leaves, switches modes, disconnects, or times out.
- Keyless text: existing Cloudflare `/api/guest/text` route with D1 quotas (12 messages/day), no API key in the browser, no microphone. **It is not the same voice Live grant.**
- Keyless voice: existing 5-minute `/api/guest/token` Live route and signed-in member quotas, unchanged.
- For BYOK Live text, optional `googleSearch` is configured on the Live socket; the existing transport already retries setup without unsupported tools when needed.
- A 40-second per-response timeout closes a nonresponsive socket and lets the next message start a fresh session.
- No transcript is persisted from this text panel.
- The session's actual microphone/no-audio behavior is covered by `tests/crew-live.lifecycle.test.js`.

## Release acceptance

1. `node --test tests/crew-live.lifecycle.test.js tests/guest-text-chat.test.js tests/short-chat-memory.test.js`
2. `npm run check:web`, `npm run check:i18n`, `npm run build:web`.
3. In Chrome and Android WebView with a verified BYOK Key, enter Teacher/Friend text and send messages. There must be no microphone prompt, and both first and follow-up turns must show text replies. Confirm a single Live WebSocket per text chat.
4. Switch to voice and confirm microphone permission and playback still work as before.
5. With no Key, continue using the Worker free text mode. If the Worker is not yet deployed, this route must say unavailable rather than attempting to use someone else's Key. Confirm Cloudflare Workers Builds separately.
